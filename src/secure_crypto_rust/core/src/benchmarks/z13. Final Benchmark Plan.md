# Benchmark

Here’s a structured benchmark plan tailored for our project layout and streaming crypto pipeline design:

---

## 🧪 Benchmark Categories

1. **I/O Throughput**
   - File → File
   - Memory → Memory
   - File → Memory
   - Memory → File
   - Socket → Socket (optional integration)

   - 🧪 Benchmark File: `secure_crypto_rust/core/benches/bench_io_throughput.rs`

2. **Pipeline Parallelism**
   - Vary `ParallelismConfig` (1, 2, 4, N workers)
   - Measure scaling efficiency

   - 🧪 Benchmark File: `secure_crypto_rust/core/benches/bench_parallelism.rs`

3. **Segment/Frame Granularity**
   - Small segments (KB range)
   - Large segments (MB range)
   - Boundary cases (exact frame size, off-by-one)

   - 🧪 Benchmark File: `secure_crypto_rust/core/benches/bench_segment_sizes.rs`

4. **Digest Algorithm Variants**
   - SHA-256
   - SHA-512
   - BLAKE-3
   - Extensible digest algorithms

   - 🧪 Benchmark File: `secure_crypto_rust/core/benches/bench_digest_variants.rs`

5. **Error & Recovery**
   - Inject corruption mid-stream
   - Cancel pipeline mid-segment
   - Resume from last successful segment

6. **Telemetry & Logging Overhead**
   - With `collect_metrics = true`
   - With async log manager enabled/disabled

---

## ✅ Summary

- Benchmarks validate **throughput, scalability, correctness, and recovery**.
- Each benchmark produces a `TelemetrySnapshot` with metrics (segment count, frame count, elapsed time).
- Recovery benchmarks ensure resumable pipelines can continue from partial output without reprocessing.

## 🧩 Notes

- **Isolation**: Benchmarks should run in `secure_crypto/core/benchmarks` with reproducible inputs (fixed seeds, deterministic payloads).
- **Repeatability**: Use deterministic test harness (join worker threads before summary).
- **Recovery**: Implement resumable pipeline trait (`ResumablePipeline`) with `checkpoint()` and `resume_from(segment_index)` methods.
- **Metrics**: Capture throughput (MB/s), latency per segment, CPU utilization, memory footprint.

## ▶️ Running Benchmarks

1. Navigate to `secure_crypto/secure_crypto_rust/core`
2. Run with Cargo:

   ```bash
   cargo bench
   ```

3. For targeted benchmarks:

   ```bash
   cargo bench --bench throughput
   cargo bench --bench recovery
   ```

4. Collect results in `target/criterion` (Criterion.rs default).
5. Compare across configurations (parallelism, digest algorithms, recovery enabled).

## 📝 Full Plan

### 1. Input/Output Cross Matrix

We want to benchmark different combinations of **InputSource** and **OutputSink**.  
The matrix looks like this:

| Input → Output | Memory                | File                | Reader/Writer         |
|----------------|-----------------------|---------------------|-----------------------|
| Memory         | ✅                    | ✅                  | (possible via Writer) |
| File           | ✅                    | ✅                  | (possible via Writer) |
| Reader         | (possible via Memory) | (possible via File) | ✅                    |

So, we can define functions like:

- `bench_v2_memory_2_memory_sync`
- `bench_v2_memory_2_file_sync`
- `bench_v2_memory_2_writer_sync`
- `bench_v2_file_2_memory_sync`
- `bench_v2_file_2_file_sync`
- `bench_v2_file_2_writer_sync`
- `bench_v2_reader_2_writer_sync`
- `bench_v2_reader_2_memory_sync`
- `bench_v2_reader_2_file_sync`

This gives us **cross coverage** (different input/output types) and **linear coverage** (same type → same type).

---

### 2. Benchmark Flow

Each benchmark function follows the same flow:

1. **Generate input data** (random bytes if memory-backed).
2. **Encrypt phase**:
   - Measure memory before.
   - Record start time.
   - Call `encrypt_stream_v2`.
   - Collect telemetry snapshot.
   - Build `BenchmarkResult`.
3. **Decrypt phase**:
   - Measure memory before.
   - Record start time.
   - Call `decrypt_stream_v2`.
   - Collect telemetry snapshot.
   - Build `BenchmarkResult`.
4. Return `[encrypt_result, decrypt_result]`.

---

### 3. TelemetrySnapshot Integration

- `output: Option<Vec<u8>>` is populated only if the sink is memory-backed.
- For file-backed sinks, `output` is `None`.

---

### 4. Implementation Strategy

- Use helper functions:
  - `random_bytes(size: usize) -> Vec<u8>`
  - `measure_memory_mb() -> f64`
  - `make_result_v2(...) -> BenchmarkResult`
- Keep the benchmark function **deterministic** and **self-contained**.
